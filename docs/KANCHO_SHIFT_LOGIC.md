## 1. データモデル

### 1-1. `kancho_members`（枠＋現在の担当者を1行で表す名簿）

「行＝人」ではなく「行＝枠（役割・班色・並び順は固定）」で、担当者は月度ごとに変わり得る（2026-07-28の再設計で分離。詳細は9章）。

| カラム | 意味 |
|---|---|
| `id` | 主キー（月度ごとに別の行＝別のid） |
| `name` | 表示名。空き枠は`(空き枠)`固定文字列 |
| `role` | `昼日勤班長`/`終業班長`/`教育班長`/`研修課出向`/`職員当直`（意味を持つのはmainのみ） |
| `section` | `'main'`（本表）/`'s1'`（①表）/`'s2'`（②表） |
| `sort_order` | 表内の並び順 |
| `is_active` | 0で一覧から除外（過去シフトは残る論理削除） |
| `team_color` | 班色（`#rrggbb`）。2人1組の班を表す。NULL=班色なし |
| `is_indoor` | 1=内勤（表に表示）／0=乗務中（名簿には残すが非表示） |
| `is_rookie` | 「班長になって日が浅い新人班長」フラグ。当直禁忌ペアの自動判定専用。**社員マスタ全体の「新人（研修中）」概念とは無関係** |
| `year`/`month` | 名簿は月度ごとに完全独立したデータ |
| `emp_no` | 社員番号。`employees.emp_no`と直接紐づけ。希望休フォームの本人確認・個人別確認ページの検索キー |
| `slot_key` | 枠の月度をまたぐ同一性を追跡するキー。将来月度への自動伝播に使用（2-3節） |

`prev_id`/`next_id`はテーブルの列ではない。ページ表示時にSQLで都度算出される仮想列（2-4節）。

### 1-2. `kancho_shift_types`（記号マスタ）

| カラム | 意味 |
|---|---|
| `code` | 記号本体（`直`,`遅`など）。**`kancho_shifts.code`はテキストで直接保存するため、マスタを削除しても既存表示は残る** |
| `label` | 凡例の説明文 |
| `color` | セル背景色（班色より優先度は低い） |
| `section` | `'main'`/`'sub'`/`'all'` |
| `daily_required` | 日別必要人数。0より大きい記号は「日別必要人数チェック行」として表に自動追加 |
| `count_in_summary` | 旧集計フラグ。**現在は未使用（互換のため残置のみ）** |
| `use_team_color` | 1ならセル背景に班色を使う（初期値: 直・遅・早） |
| `counts_as_work` | 出勤数カウント対象 |
| `counts_as_off` | 公休数カウント対象 |
| `show_in_input` | 入力モーダルのプリセットボタンに表示するか |
| `year`/`month` | 記号一覧も月度ごとに独立データ |

### 1-3. `kancho_shifts`（実シフトセル、1メンバー1日1件、PK=`member_id,date`）

| カラム | 意味 |
|---|---|
| `code` | 記号テキスト（空文字＝色マスのみの早日勤もあり得る） |
| `is_diagonal` | 斜め直（斜体表示） |
| `is_wish` | 希望休反映済み（赤文字） |
| `cell_color` | セル個別色の上書き（他班ヘルプ等）。NULL=自動（班色 or 記号色） |
| `is_locked` | 確定ロック。1の間は内容変更をブロック（migration_074） |

> **重要な設計不変条件（2026-08-08、ユーザー明示）**: `kancho_shifts`は`member_id`（＝枠のid）に紐づいており、担当者の「人」には紐づいていない。担当者変更（`/api/kancho/members/:id/link`）は`kancho_members.name`/`emp_no`だけをUPDATEし、`kancho_shifts`には一切触れない（コードで確認済み）。つまり**人を入れ替えても、その枠に既に入力されているシフトは絶対に消えたり変わったりしてはならない**。唯一の例外は「並び替え（D&D・sort_order変更）」で、これは枠自体の並び順を変えるだけの操作であり問題ない。今後この機能に手を入れる際は、担当者変更・紐付け解除などの操作がうっかり`kancho_shifts`を削除・移動する実装にならないよう常に注意すること。

### 1-4. その他テーブル

- **`kancho_memos`**: `kind='tokki'`（特記事項フリーテキスト）／`kind='kibou'`（旧来のフリーテキスト希望休）。**構造化された`kancho_wishes`とは完全に別物**（両者は同期しない）。
- **`kancho_edit_logs`**: `action`は`shift`/`member`/`type`/`memo`/`wish`/`notify`。全編集操作を記録。
- **`kancho_forbidden_pairs`**: 当直禁忌ペア。`member_id_a < member_id_b`で正規化、`UNIQUE(member_id_a, member_id_b)`。
- **`kancho_wishes`**: 構造化希望休。`UNIQUE(member_id, date)`。「希望休を自動反映」ボタンの元データ。
- **`kancho_wish_remarks`**: 希望休フォームの「その他要望」欄。`member_id`主キーで**最新内容のみ**保持（履歴なし）。
- **`kancho_wish_notify_optin`**: 希望休の提出・取消時に即時LINE通知する送信権限者。ロール制限なし。0時の出勤者通知先`kancho_notify_optin`とは**別テーブル**（こちらは`general_manager`/`operations_manager`のみ登録可）。
- **`kancho_wish_settings`**: id=1固定の単一行。`target_year`/`target_month`（募集対象月度）、`open_from`/`open_until`（受付期間）。
- **`kancho_calendar_notes`**: 個人別確認ページの「その他」自由記述欄（内勤・乗務共通、本人以外も編集可）。
- **`kancho_crew_schedules`**: 乗務班長(`is_indoor=0`)用の個人スケジュール専用テーブル。**現状は書き込みAPIが存在せず常に空**（将来拡張の受け皿）。

## 2. 月度ごとのコピー・伝播ロジック

### 2-1. 月度の考え方

`auth.ts`の`getPeriod()`: 締め日以降（デフォルト18日）は翌月度扱い（`period_settings`で月ごとに変更可）。`getShiftDisplayRange()`は表示上、月度の前後3日を広げた範囲を返す（月またぎの薄グレー表示のため）。

### 2-2. `ensureKanchoPeriod`（`admin_kancho.ts`）

新しい月度のページを開いたとき1回だけ実行される初期化:

1. その`year/month`の`kancho_members`が0件なら、直前の月度（無ければ直後）を探し、全行を新IDでコピー（`slot_key`はそのまま引き継ぎ＝同じ枠として継続）。
2. コピー元月度の`kancho_forbidden_pairs`のうち両者が同月度にいるペアだけ新IDにマッピングして複製。
3. `kancho_shift_types`も0件ならコピー（`slot_key`のような同一性キーは無く単純複製）。

呼び出し箇所: `/kancho-shift`ページGET時、`/kancho-shift/print`、希望休の募集設定保存時（対象月度を切り替えると自動で名簿が用意される）。

### 2-3. `slot_key`による将来月度への自動伝播

「枠の設定は意図的に変更しない限り、既に開かれている将来の月度にも同じ設定を使い続ける」運用。

- **`propagateForward(db, memberId)`**: 対象メンバーの`slot_key`が非NULLなら、**既に存在する**より後の月度で同じ`slot_key`を持つ行すべてに name/role/section/sort_order/team_color/is_indoor/is_rookie/is_active/emp_no を一括UPDATE。呼び出し箇所: メンバー編集PUT・一括保存・担当者変更link（移動元の空き枠化も含む）・社員管理照合link/register。
- **`createInFuturePeriods`**: 新規に枠を追加した時、既に存在する将来月度すべてに同じ`slot_key`の空き枠を複製挿入。

**枠(kancho_members)の編集はすべて`slot_key`をキーに「未来の既存月度」へ伝播する。過去月度へは伝播しない。** 伝播先の月度自体がまだ開かれていなければ`ensureKanchoPeriod`実行時にコピーされる。

### 2-4. `rowMatchSql`（月またぎのグレー表示・氏名照合）

ページ表示SELECT時にのみ計算される読み取り専用の`prev_id`/`next_id`。

- `emp_no`が紐付いていればそれを最優先で前後月度から照合。
- 未紐付けなら`section`/`team_color`/`role`/`sort_order`の完全一致（NULL同士も一致とみなす）でフォールバック。
- 表示日が現月度より前なら`prev_id`のシフトを、後なら`next_id`のシフトを、**自分のセルが空の場合だけ**補完表示する（保存は常に自分のID宛て。あくまで視覚効果）。

旧「表示名の旧名→新名矢印」ロジック（`nameLabel()`、人単位の`prev_member_id`）は2026-08-08に廃止済み。現在は常に`kancho_members.name`をそのまま表示する。

### 2-5. 印刷ページも前後3日分を表示（2026-08-08実装）

終業班長の締め日ずれ（3-6節）等のイレギュラーを確認できるよう、印刷ページ(`/kancho-shift/print`)も通常のシフト表画面と同じ`getShiftDisplayRange`（月度の前後3日）・`rowMatchSql`によるprev_id/next_id照合を適用するように変更した。以前は印刷は月度内の日付のみで前後の余白日を含めなかった。月度外の日付列はヘッダーを半透明（`opacity:0.5`）にして参考表示であることを示す。

## 3. 記号・勤務時間のルール

### 3-1. 時間帯の凡例

| 記号/状態 | 時間帯 |
|---|---|
| 直（通常） | 9:00〜翌3:00 |
| 直（`is_diagonal=1`、斜め直・斜体表示） | 14:00〜翌8:00 |
| 遅 | 10:00〜19:00 |
| 終業班長の空白＋班色（＝出勤扱い） | 3:00〜12:00固定（UI凡例文言。データ上は他役職の早日勤と同じ「記号なし＋cell_color」形式で、意味付けは`role`で変わる） |
| 記号なし＋色付き（早日勤、役職不問） | 7:30〜16:30 |
| 空白（白マス） | 未入力 |

### 3-2. セル背景色の決定優先順位

1. `cell.cl`（セル個別色上書き、他班ヘルプ等）が最優先
2. `code`があり、その記号が`use_team_color`かつ本人に`team_color`があれば班色
3. それ以外は記号マスタの`color`（無ければ既定色）
4. `code`も`cl`も無い完全な空欄は白＝未入力

「早日勤で出勤」は**記号なし＋`cell_color`のみ**の状態として明示保存される。色は選択色優先、なければ本人の班色を使用。班色未設定なら保存を拒否しトースト表示。

### 3-3. 「明」記号の廃止

明け・非番も出勤数カウント対象化された後、**「明」記号自体を廃止**し既存データは`非`へ一括変換・マスタからも削除済み。以降「非」記号が制度上つねに「明け」を意味する（個人別確認ページでは表示ラベルを「明け」に上書き表示）。

### 3-4. 直の翌日に非を自動セット

`counts_as_work`対象は`直`/`遅`/`早`/`非`。

以下3箇所で同一ロジック（重複実装）:
1. 通常のセル編集モーダル適用時: `code==='直'`のセル確定後、翌日セルが**白（未入力かつcell_colorも無し）でロックされていない**場合のみ`非`を自動セット（斜め直なら`is_diagonal`も引き継ぐ）。
2. コピペ編集モードでの貼り付け時も同条件で発火。
3. 「希望休を自動反映」実行時: 既存の`直`セルを全走査し、翌日が空白かつロックされていなければ`非`を自動設定（翌日に希望休が既にあれば公休優先でスキップ）。

いずれも**確定（ロック）済みのセルには自動セットしない**。

### 3-5. 出勤・公休カウント（右端固定4列）

固定4列: `work`(出勤)/`off`(公休)/`choku`(直)/`oso`(遅)。

- `work`: `code===''`なら`cell.cl`があればカウント（早日勤/出勤扱いの色マス）。それ以外は`counts_as_work=1`の記号（直・遅・早・非）
- `off`: `counts_as_off=1`の記号（公・指公・夏など）
- `choku`: `code==='直'`のみ（**斜め直も同じ「直」コードなので合算される**）
- `oso`: `code==='遅'`のみ

日別必要人数チェック行は`daily_required>0`の記号のみ表示。当日のmainセルで記号一致数をカウントし`n/req`表示、一致すれば緑、不一致なら赤。

### 3-6. 斜め直・終業班長の運用ルール（2026-08-08追記、ユーザー説明）

斜め直（14:00〜翌8:00）と終業班長固定勤務（3:00〜12:00）の関係には、以下の実運用ルールがある。

- **斜め直当日の12:00〜14:00の穴**: 終業班長は12:00に勤務終了、斜め直は14:00開始のため、同じ日に終業班長が出勤し、かつ夜から斜め直が入る場合、12:00〜14:00はどちらの勤務者もカバーしていない空白時間になる。この穴は、**同じ課の別の昼日勤班長がその日に早日勤または遅日勤で出勤する**ことで埋める必要がある（例: 18日に黄色＝2課の1人が斜め直に入るなら、もう1人の黄色枠の昼日勤班長がその日に早日勤か遅日勤で出勤している必要がある）。
- **斜め直は終業班長に休みを与えるための勤務**: 斜め直が入った日の翌日は、その課の終業班長は休みになる（休みにするために斜め直を組む、という因果関係）。斜め直は翌朝8:00までしかカバーしないため、終業班長が休みのその翌日は8:00以降（本来なら終業班長が12:00まで担当する時間帯）も**同じ課の別の昼日勤班長が早日勤として出勤している**必要がある。
  - これは既存の警告チェック（7章「課の3:00〜12:00カバレッジ」）の「前日斜め直＋当日同課の日勤→実質カバー」ヒューリスティックと整合する内容で、このヒューリスティックが存在する理由そのものにあたる。
- **2026-08-08実装**: 「斜め直当日の12:00〜14:00の穴」を検知する自動警告を追加した（詳細は7章「警告チェック機能」参照）。
- **終業班長の勤務パターン**: 終業班長は当直・遅番等を持たず全て日勤（3:00〜12:00固定）のみ。月間の出勤日数は色付きマス（早日勤と同じ形式のセル）が25個あれば足りる。
- **締め日と終業班長シフトの1日ずれ**: 締め日が17日（18日始まり）の運用で、その社員が17日に出勤した場合、その勤務実績は「18日の終業班長枠」の実績として扱う。つまり**終業班長の枠だけ、表示上シフトが1日後ろにずれる**（他の役職にはこのずれは無い）。

## 4. 班色ルールと自動付与・上書き

- 班色初期値: 黄緑・黄色・水色・ピンク（当初は特定の名前に直接割当、以後は枠編集で自由設定）。色選択肢には赤・グレー・白も追加。
- 記号色ルール: 班色系記号（公・非・明・指公・○・直・遅・早）は素の記号色を白にし、実際の色は班色/セル個別色で決める。採・夏・Mは赤固定（休暇系を目立たせる）。
- 名前セル左端の縦バーで班色を可視化。
- **警告チェックの「課」判定**（7章）は`team_color`を課色マップ（黄緑=1課, 黄色=2課, 水色=3課, ピンク=4課）にマッピングして使う。カスタム色（赤/グレー/白等）は課判定の対象外。
- **セル個別色（`cell_color`）**は「他班ヘルプ等」用途。班色・記号色より常に優先。

## 5. 編集モード・コピペ編集モード

### 5-1. 通常編集モード

- 「編集モードを開始」で`_editMode=true`。未保存変更があれば離脱前に確認。
- セルタップは`document`レベルのイベント委譲でモーダルを開く（色付きマスでもタップできるよう堅牢化済み）。
- モーダル: 記号自由入力欄＋プリセットボタン（`show_in_input=1`かつsectionが一致するもののみ）、斜め直チェック、希望休反映チェック、セル色セレクト、ロックチェック。◀▶で同一メンバーの前後日付へ一時反映しながら移動できる。
- **ロック中の挙動**: 記号入力・斜め直・希望休・色・クリア・プリセットボタンをすべて無効化し、ロックのON/OFF自体と◀▶ナビだけ操作可能。
- 保存はローカルに溜め、「一括保存」で`/api/kancho/shifts/batch`へ送信。サーバー側は`is_locked=1`かつ内容変更ありのセルをブロック件数としてカウントし保存しない。

### 5-2. コピペ編集モード

- コピー元セル選択→貼り付け先を連続タップ、記号・斜め・希望休・セル色を丸ごとコピー。
- ロック済みセルへの貼り付けは拒否。コピー元自身への貼り付けは無視。
- 貼り付けた記号が`直`ならここでも「翌日に非」自動セットが発火。

## 6. 名前D&D並び替え・①②表開閉

- **名前D&D並び替え**: 編集モード中のみ有効。同じ表(main/s1/s2)かつmainは同じ役割グループ内のみ並び替え可。ドロップした瞬間に`/api/kancho/members/batch`へ**即時保存**（一括保存ボタン待ちではなく、編集モードの保留変更とも独立）。
- **①②表の開閉トグル**: 見出しクリックで表全体を開閉。状態はDBでなくlocalStorageに保存＝**自分のブラウザだけ**記憶、他の人の表示には影響しない。
- **印刷ボタンの位置（2026-08-08変更）**: 以前はツールバーに常設ボタンがあったが、⚙️歯車メニュー内の先頭項目（「印刷」）に格納された。閲覧権限のみでも利用可能（`canEdit`不問の項目として配置）。

## 7. 警告チェック機能

ボタン押下時だけでなく再計算のたびに常時バッジ更新。**すべて警告表示のみで保存はブロックしない。** 対象は`section==='main'`かつ`is_active=1`かつ`is_indoor=1`のメンバー、判定範囲は月度内の日付のみ（①②表は対象外）。

1. **当直・遅日勤の頭数不足**: 記号マスタの`daily_required`（`直`=2, `遅`=1が初期値）と当日の実カウントを比較。不足があれば警告。
2. **当直の禁忌ペア**: 当日の当直メンバー全組み合わせをチェック。①`is_rookie`が両者ともtrueなら「新人班長同士」を自動警告（登録不要）。②`kancho_forbidden_pairs`に登録されているペアなら理由付きで警告。
3. **課の3:00〜12:00カバレッジ**: 各課の`終業班長`役割メンバーのうち誰か1人でも当日出勤していればカバー済み。カバーされていない場合はヒューリスティックな救済判定を追加で行う。
   - 前日に同課メンバーの斜め直があり、当日に同課メンバーの日勤（早日勤色マス or `早`記号）があれば実質カバーとしてスキップ。
   - 前日斜め直＋当日通常直の場合は警告ではなく参考注記（グレー）で「8:00〜9:00頃のみ要確認」。
   - それ以外は赤い警告「3:00〜12:00がカバーされていない可能性」。
4. **斜め直当日の12:00〜14:00カバレッジ（2026-08-08実装）**: 終業班長が当日出勤しており（＝3.のカバレッジ判定でカバー済みと判定された日）、かつ同課の誰かがその日に斜め直（`code==='直'`かつ`is_diagonal=1`）で入っている場合、終業班長の勤務終了(12:00)〜斜め直の開始(14:00)の間は誰もカバーしない穴になる。同課の別メンバー（**終業班長本人は除外**。終業班長の空欄＋班色セルは早日勤と見た目のデータ表現が同一のため、誤って早日勤扱いしないよう明示的に除く）が、その日に遅日勤(`遅`)・早日勤(空欄+色 or `早`)・通常直(`直`かつ非斜め)のいずれかで出勤していればカバー済みとみなす。カバーされていなければ警告「斜め直当日の12:00〜14:00がカバーされていない可能性（同課の早日勤・遅日勤が必要）」。
5. **連勤検知**: 出勤（出勤扱いの記号 or 非 or 早日勤色マス）を日付順にカウントし、**streakが10に達した時点で「10日以上の連勤」として警告**（明けも連勤日数に含む）。

いずれも`section='main'`のみが対象で①②表は警告チェックの対象外。

### 7-1. 課の判定は「日別の実効班色」ベース（2026-08-08修正）

上記3.・4.の「課」グルーピングは、以前はメンバーの`team_color`（月を通じて固定）だけで判定していたが、**「1課の班長がその日だけ2課を手伝う」といった臨時のクロス課対応があり得る**（ユーザー明示、2026-08-08）ため、日別に「その日のセルの`cell_color`（他班ヘルプ用の個別色上書き）があればそちらを優先し、無ければ`team_color`」で所属課を判定するように修正した（`_deptOf(m, d)`関数）。これにより、ある班長がその日だけ`cell_color`を他課の色にして手伝った場合、その日はその課の一員として頭数・カバレッジ判定に数えられる（元の課の判定には数えられない）。「前日斜め直」の判定も同様に、前日時点の実効班色でその日のメンバーを再判定する。

## 8. 権限モデル

`admins.permissions`がNULLなら全権限。JSON配列を持つ制限アカウントは、キー`X`で閲覧(GET)のみ、`X.edit`が無ければ非GETは全て拒否。

| キー | 対象パス | 用途 |
|---|---|---|
| `kancho-shift` | `/kancho-shift`（本体・印刷・個人別確認含む）、`/api/kancho/*` | 班長シフト表の閲覧全般 |
| `kancho-shift.edit` | 同上の非GET | シフト保存・名簿/記号編集・希望休登録など |
| `settings.kancho` | `/settings/kancho`（ハブページ） | 班長関連メニューのトップ |
| `settings.kancho-roster` / `.edit` | `/settings/kancho-roster`, `/api/kancho-roster*` | 班長リスト閲覧／班長登録解除の編集 |
| `settings.kancho-wish` / `.edit` | `/settings/kancho-wish`, `/api/kancho-wish-settings*` | 希望休フォーム設定閲覧／編集 |
| `settings.kancho-logic` | `/settings/kancho-logic` | ロジック仕様書ページの閲覧（本ドキュメントの管理画面版。編集操作なしのため`.edit`キーは無い） |

`admin_kancho_personal.ts`の`/api/kancho-personal/*`は例外的にグローバルの`.edit`必須ルールをバイパスし、**閲覧権限(`kancho-shift`)のみでその他メモの書き込みまで許可**する特殊対応（一般閲覧者でも自分の「その他」メモを保存できるようにするため）。

## 10. 実装上の注意点（要確認事項含む）

1. `kancho_shift_types.count_in_summary`は現在未使用（互換のため残置のみ）。出勤/公休/直/遅カウントは`counts_as_work`/`counts_as_off`/コード直接比較で行う。
2. `kancho_memos`(`kind='kibou'`、フリーテキスト希望休)と`kancho_wishes`(構造化希望休)は名前が紛らわしいが完全に別データ・別UI。片方の編集はもう片方に影響しない。
3. `kancho_crew_schedules`（乗務班長の個人スケジュール）は現時点で書き込みAPIが存在せず、常に空テーブル。
4. `prev_id`/`next_id`はDBカラムではなく表示時に動的計算される仮想フィールド。
5. **連勤警告の閾値は実装上「10連勤」**。企画段階のヒアリングメモには「7日間以上」という記述が残っていたが、実装（コード・UI文言とも一貫）は10連勤。運用上どちらが正しいかは要確認。
