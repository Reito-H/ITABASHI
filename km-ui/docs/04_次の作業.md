# 04. 次の作業(優先順)

## フェーズ 1: Cloudflare Workers で実データ表示(読み取り専用)
1. `cloudflare-worker/` を `wrangler deploy`。`*.workers.dev` で `/api/health` が返ることを確認
2. `https://<worker>/kmx/HS/HSHS/HSHS0199.do` を開き、テストアカウントでログイン → Cookie が Worker ドメインに付くことを DevTools で確認
3. `https://<worker>/` で通知バーに「LIVE 実データ(読み取り専用)」が出ることを確認(`/api/session` が operatorId を返す)
4. 伝票検索・地図・営業情報・走行軌跡・マスタが実データで動くことを確認。エラーは `msgs[].msg` を見て `live.js` のパラメータを修正
5. Cloudflare Access を設定し、社内アカウント以外を遮断

## フェーズ 2: ログインを新UIに取り込む
- 旧ログイン画面(HSHS0199)の送信先・フィールド名・ハッシュ化有無を Network タブで確認し、新UIにログインフォームを実装
- `api/v1/SessionEnsure` を定期呼び出し(旧UIと同じ間隔)してセッション維持
- ログアウト: `api/v1/auth/logout`

## フェーズ 3: 書き込み系
- Worker `READ_ONLY=false`、`live.js` の `API.post` 実装
- 優先: 伝票保存(create_ticket / update)→ 探車(find_and_dispatchs/confirm)→ 配車依頼(map_vehicles/dispatch_request)→ 個別メッセージ(center_messages/create)
- 旧UIの `$cf.ajaxPost` の payload を Network タブで取得して合わせる。排他ロック(`exclusion_check` / `switching_exclusion_lock`)も同時に
- 本番データへの影響があるので、BIPROGY に検証環境の有無を確認してから

## フェーズ 4: 残り画面と地図
- 問合せ伝票・忘れ物伝票の専用フォーム(旧画面の項目: 問合せ種別、受付日、対象、発生日時、発生場所、営業所、無線番号、乗務員名、添付 2 件、ステータス、内部用メモ)
- 場所検索(施設/住所/配車先、都道府県絞込)と場所リスト検索
- ZENRIN 地図(許可ドメイン追加を依頼 → `map.js` の描画を zmaps に差し替え)
- 一斉送信/SOS/予約本数表(権限のあるアカウントで旧画面と API を確認)
- 乗務員連絡(未読一覧と既読化 `driver_messages/update`)

## フェーズ 5: 品質
- 旧UIが数秒おきに叩く通知 API を 1 本化できないか検討(サーバー変更不可なら呼び出し間隔を 15〜30 秒に)
- キーボード操作(Ctrl+S 保存、Ctrl+Enter 検索、Esc 閉じる は実装済み)の拡充。電話受付中の片手操作を想定
- アクセシビリティ(フォーカス可視、コントラスト)、1280px 未満での崩れ確認
- 必要なら React/Vue 化。API 層(`live.js`)と列名はそのまま流用可能
