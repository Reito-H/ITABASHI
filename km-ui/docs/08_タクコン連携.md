## 板橋 PC 側に設置済みのもの(takcon-sync)
- 常駐 `C:\Users\taxic212\takcon-sync\takcon-sync.ps1`(ログオン時タスク `takcon-sync`、`config.json` で設定)
- 見張る場所: 上記の共有フォルダ(ファイルは動かさず `state.json` に処理済みを記録)+ 手動投入フォルダ `Desktop\事故データアップロード\送信待ち`
- 2026-10-13 より前のファイルは「手動で取込済み」として基準登録済み。以後に出力された CSV だけが未処理として見える
- **pull API**(今すぐ使える)`http://127.0.0.1:8766`:
  - `GET /health` → `{ok, pending, sources:[{label,reachable}], time}`
  - `GET /files?kind=<種別>` → `{files:[{name, kind, size, modified, source}]}`(kind は ホシコン収集データ / 事故データCSV / 日報データCSV / 駐車料金 / オット / その他)
  - `GET /file/{name}` → CSV 本体(text/csv, Shift-JIS のまま。レスポンスヘッダー `X-File-Kind`)
  - `POST /ack/{name}` → 処理済みにする(次回から一覧に出ない)
  - `config.json` の `serveToken` を設定すると `Authorization: Bearer <token>` 必須(設定推奨。値は別経路で共有)
- **push**(任意): `config.json` の `uploadUrl`/`uploadToken` を設定すると 20 秒ごとに `POST uploadUrl`(本文=CSV, ヘッダー `X-File-Name`, `X-File-Kind`(URL エンコード), `X-Source: takcon`, `Authorization: Bearer`)。2xx で処理済み

## ホシコン側でやること(案 pull 推奨)
1. 既存 Tunnel(km-relay)に Public Hostname を 1 本追加: `takcon.bentenclub.com → http://localhost:8766`(Zero Trust → Tunnels → km-relay → Public Hostname)。板橋 PC 側の変更は不要(トークン接続なのでダッシュボード設定が自動反映)
2. そのホスト名に Cloudflare Access(サービストークン)を付け、ホシコンの Worker からのみ到達可にする
3. Worker に Cron Trigger(例: 15 分ごと): `GET /files` → 種別ごとに `GET /file/{name}` → 既存の CSV 取込処理(ホシコン収集データ・事故データなど、今まで手でアップロードしていたものと同じ処理)→ 成功したら `POST /ack/{name}`。失敗したら ack しない(次回再試行)
4. 板橋 PC 側の `serveToken` を設定(Windows 側 Claude か手動)
5. 取込結果をホシコンの画面に出す(「最終取込 日時 / 件数 / 失敗」)。失敗が続いたら通知

## 決定事項(2026-10-13 夜)
- **採用する方式: 共有フォルダ監視 + ホシコンが pull**。タクコン側の操作は「CSV 出力」のみ残す
- SQL Server 直読みは当面見送り。理由: タクコンのログイン ID(アプリ内 ID)は SQL ログインではなく「ログインできませんでした」になった。板橋 PC の Windows アカウントにもログインが無い。社内で SQL Server の管理者アカウント(sa 等)が不明になっている可能性がある
- DB 直読みを再開する条件: IT 担当または開発元(SystemOrigin)が、`E210赤羽` と `Taxcon` の db_datareader だけを持つ読み取り専用ログインを発行する(管理者不明ならシングルユーザーモードでの管理者復旧が先)。依頼文は板橋側で用意済み
- したがって Mac 側の作業は上記「ホシコン側でやること(案 pull)」の 1〜5 だけ

## さらに「出力」操作もなくす(フェーズ 2、読み取り専用ログイン発行後)
SQL Server に直接読みに行けば、タクコンの「CSV 出力」ボタンも不要になる。必要なもの:
- IT 管理者(または SystemOrigin)に **読み取り専用の SQL ログイン**(`E210赤羽` と `Taxcon` の db_datareader)を作ってもらう
- 事故データ・日報・収集データに対応するテーブル名と列(SystemOrigin の仕様書は `C:\Taxcon\国際自動車\仕様書\` にあるとされる)
- 板橋 PC の `C:\Users\taxic212\takcon-sync\takcon-db-export.ps1`(雛形あり。SQL Server 用)に接続先・クエリを入れ、毎朝タスクで実行 → 送信待ちに CSV を置く → 以後は同じ経路
- 認証情報は環境変数 `TAXCON_DB_USER/PASS`(または資格情報マネージャー)。ファイルに書かない

## 注意
- CSV には個人情報(乗務員氏名・社員コード・事故情報)が含まれる。Tunnel ホスト名には必ず Access を付け、Worker のログに本文を出さない
- 共有フォルダは他部署も使っているため、板橋 PC 側はファイルを移動・削除しない(記録のみ)
- 板橋 PC が落ちている間は止まり、復帰後に未処理分から再開する
