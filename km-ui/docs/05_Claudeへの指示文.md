あなたには、タクシー配車システム「クラウド配車システム(km-operator)」の画面を最新 UI に作り直すプロジェクトを引き継いでもらいます。前任の Claude が調査と新 UI のプロトタイプ、実データ接続層、Cloudflare Workers 版リバースプロキシまで作ってあります。まず次の順で読んでください。

1. `README.md`(全体像)
2. `docs/01_調査結果.md`(既存アプリの技術構成、API 一覧、確認済みパラメータと応答、コード値)
3. `docs/02_アーキテクチャと配置.md`(Cloudflare Workers での配置、ログインの流れ、セキュリティ)
4. `docs/03_新UIの構成.md`(ui/ の各ファイルの役割と既知の制限)
5. `docs/04_次の作業.md`(優先順の作業リスト)

前提と制約:
- サーバー(km-operator)は変更できません。既存の `/kmx/api/v1` JSON API をそのまま使います。
- 本番データ(顧客の氏名・電話番号・住所)が API 応答に含まれます。応答の中身をチャット、ログ、資料、コミットに貼らないでください。確認が必要なときはキー名と件数だけを扱ってください。
- `tickets/get_init_display_data` の応答には地図サービスの鍵や各種パスワードが入っています。表示・保存しないでください。
- 現時点では読み取り専用です。書き込み系 API(create/update/delete/send/confirm/dispatch_request)は、私が明示的に許可するまで呼ばないでください。Worker の `READ_ONLY` と `live.js` の `API.post` がそれを止めています。
- テストアカウントの ID とパスワードは別途渡します。ログイン操作は私が行います。あなたはパスワードを入力しないでください。

最初のタスクは `docs/04_次の作業.md` のフェーズ 1 です。`cloudflare-worker/` を私の Cloudflare アカウントにデプロイできる状態にし、デプロイ後に実データで伝票検索・地図・営業情報・走行軌跡・マスタが動くかを一緒に確認してください。エラーが出たら、API の `msgs[].msg`(日本語のバリデーションメッセージ)を手がかりに `ui/live.js` のパラメータを直してください。

分からないことがあれば、推測で進めずに聞いてください。特にログインフォームの送信先と、`vehicles/search` などの `searchKind` の値は未確認です。
