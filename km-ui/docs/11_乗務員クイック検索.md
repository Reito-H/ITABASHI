# 11. 乗務員クイック検索(右下フローティング) — ホシコン側への組み込み依頼

作成: 2026-10-14(Windows 側 Claude)。要望: 「この人は今日どの車に乗っているか」を名前で爆速検索し、無線番号と現在地の住所を出す。配車コンソールの外(ホシコンの任意の画面)に置く。

## 成果物
- `ui/driver-finder.js` … 独立部品。配車コンソールに依存しない。1 行で組み込める
- `ui/driver-finder.html` … デモ(架空データ)。右下の「乗務員検索」または `Ctrl+/` で開く

## 組み込み方(ホシコンの共通レイアウトに 2 行)
```html
<script>window.DRIVER_FINDER = { apiBase: '/kmx/api/v1/', refreshSec: 60 };</script>
<script src="/ui/driver-finder.js"></script>
```
- 同一オリジンに `/kmx/api/v1`(km-operator へのプロキシ)があること。ホシコンでは配車コンソールと同じ経路(km-relay)で既に通っている
- プロキシのパスが違う場合は `apiBase` を変える。`fetch` を使わず独自の中継関数を使う場合は `transport: async (path, params) => json` を渡す
- 配車コンソールの `index.html` にも同梱済み(右下に出る)

## 動き
- 60 秒ごとに `map_vehicles/get_map_vehicle`(東京広域の bbox)で稼働中の全車両を取得。乗務員名(姓+名)・無線番号・状態・座標を保持
- 入力した文字で部分一致(空白・全角半角を無視)。候補 8 件。↑↓ で選択、Enter で無線番号をコピー
- 各候補について `trip_infos/get_address`(緯度経度→住所)で現在地の住所を表示(キャッシュあり)
- 車両番号は `map_vehicles/get_vehicle_info?vehicleId=` の応答から `vehicleNumber` 等のキーを拾って表示(**応答のキー名は未確認**。取れない場合は無線番号のみ表示)
- 出庫前・退勤後の乗務員は位置情報に出ないため候補に出ない(その旨を表示)

## ホシコン側で確認・調整してほしいこと
1. `map_vehicles/get_vehicle_info` の応答のキー名(車両番号/ナンバー)。分かれば `driver-finder.js` の `plate()` の候補キーに追加
2. bbox が狭ければ `DRIVER_FINDER.bbox = {nwLat, nwLon, seLat, seLon}` で広げる(横浜・成田を含めるなら seLat 35.3 / seLon 140.4)
3. 乗務員名は漢字のみ(API にカナが無い)。カナ検索が必要なら `drivers/search`(searchKind 要確認)で氏名カナ一覧を取り、名前→カナの辞書を作る拡張が可能
4. Cloudflare Access の裏で動くので、ページを開いているユーザーのセッションでそのまま動く。追加の認証は不要

## 注意
- 乗務員の氏名と位置情報を扱う。表示先の画面もログイン必須の範囲に限ること
- 60 秒ごとの取得は 1 リクエスト。既存の地図画面の負荷より小さい
