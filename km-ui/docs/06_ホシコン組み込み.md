# 06. ホシコンへの組み込み（2026-10-13 実装・本番デプロイ済み）

`02_アーキテクチャと配置.md` の「Cloudflare Workers でリバースプロキシ」案は、**Workers から km-operator への接続が 522（タイムアウト）で遮断される**ため成立しなかった（2026-09 の乗降ピン収集 v1 と同じ現象）。
代わりに、ユーザーの方針「ホシコンの中に埋め込み、ホシコンにログインしないと使えない」に合わせて次の構成にした。

## 構成
```
[オペレーターのブラウザ] ── ホシコンにログイン ──▶ https://bentenclub.com/<SECRET>/admin/km-console   … 新UI(ui/) をそのまま配信
          │ <base>/kmx/api/v1/*（GET のみ）/ <base>/session
          ▼
[ホシコン Worker  system/src/routes/admin_km_console.ts + utils/km_relay.ts]
          │ km-operator へ自動ログイン（KM_OPERATOR_LOGIN_ID/PASSWORD）。Cookie と X-CLTFT-Token は D1(km_console_session) に保持
          │ 毎リクエストに Cloudflare Access のサービストークン（KM_RELAY_ACCESS_ID/SECRET）を付与
          ▼
https://km-relay.bentenclub.com   … Cloudflare Tunnel（Access で保護。サービストークン無しは 403）
          ▼
[社内PC（日本国内IP）の cloudflared]  … km-ui/relay-pc/ の手順で設置。ログオン時に自動起動
          ▼
https://km-operator.smartaxicenter.com/kmx/…  （BIPROGY 運用、変更なし）
```

## ホシコン側の変更点
| ファイル | 内容 |
|---|---|
| `system/src/routes/admin_km_console.ts` | 画面配信（index.html を変換: Google Fonts 削除・スクリプトを `<base>/asset/*.js?v=ハッシュ` へ・`window.__KMX_BASE` 埋込・「ホシコンへ戻る」）、`/session`、`/kmx/api/v1/*`（GET のみ中継、書き込み系は名前で 403）、`/relogin` |
| `system/src/utils/km_relay.ts` | 中継クライアント。ログイン手順（ログイン画面 GET → auth/login → 実画面 GET で KMX_USER 取得）、`X-CLTFT-Token` をヘッダー＋Cookie の両方で送る、`X-Use-Cookie: true` と `X-Requested-With` を常時付ける（無いと画面 GET が短いエラーページになる）、セッション切れ時は1回だけ再ログイン |
| `system/src/assets/km_console_ui.ts` | `km-ui/ui/` を文字列として埋め込んだ自動生成ファイル。`npm run build:km-console` で再生成 |
| `system/src/db/migration_197.sql` | `km_console_session`（1行だけ） |
| `system/src/permissions.ts` / `html/layout.ts` | 権限キー `km-console`（閲覧のみ）、サイドバー「配車コンソール」（「スマタク」外部リンクの下） |
| `system/src/auth.ts` / `wrangler.toml` | `KM_RELAY_ACCESS_ID` / `KM_RELAY_ACCESS_SECRET` |

`ui/live.js` には `window.__KMX_BASE` 対応を追加した（セッション確認先を `<base>/session` に、API を `<base>/kmx/api/v1/` に。接続できない時は通知バーに赤いピルで理由を表示）。`ui/index.html` を直接開くモック動作は従来どおり。

## 確認済み（2026-10-13、Mac 上で一時的に cloudflared を動かして検証）
- 自動ログイン → `KMX_USER`（operatorId 等）取得 → `ticket_notices/*`・`map_searches/get_taxi_stand`・`offices/search`・`ticket_searches/search` が実データで応答
- `ticket_searches/search` は live.js が送る全パラメータが揃っていないと km-operator 側で応答が返らない（20秒タイムアウト）。パラメータを減らさないこと
- 書き込み系（`tickets/create_ticket` 等）は GET でも 403、POST は全て 403
- 社内PCが落ちている時は「中継PC（km-relay）がオフラインです」、Access 認証不一致は別メッセージ
