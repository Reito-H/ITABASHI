# 03. 新UI(ui/)の構成

ビルド不要の静的ファイル。`ui/index.html` を開けばモックで動く。

| ファイル | 役割 |
|---|---|
| `index.html` | シェル(ヘッダー通知バー、左レール、画面コンテナ)、デザイントークン(CSS 変数、ライト/ダーク)、伝票画面(新規伝票フォーム、伝票検索、期間ピッカー、結果テーブル、詳細ドロワー)、`API` アダプター、`MOCK`、ハッシュルーター(`route()`) |
| `screens.js` | 伝票の関連パネル(配車パネル、予約事前割当、工程、役割選択、定期予約、経由地、フライト、乗務員検索、お客様検索/詳細、一括キャンセル、印刷用表示、直近30分)、営業情報画面、メッセージ 4 種、マスタ一覧と汎用編集、CSV、SOS、時間帯別予約本数表、機能一覧表(`FUNCS`)。汎用 `modal()` |
| `map.js` | Canvas 模式地図(`makeView`)、地図・範囲検索(中心+半径/矩形/多角形、ステータス・グレード・所要時間絞込、レイヤー、無線番号ジャンプ、配車依頼)、走行軌跡(区間一覧、ステータス変化点、停車地点、速度色分け)。LIVE 時は実車両・実待機場所・実走行データに差し替え |
| `live.js` | 実サーバー接続層。`activateLive(K, transport)`。`API.get` を上書きして検索条件を実パラメータに変換し、応答を UI の列名に正規化。`LIVE.trips/drivers/vehicles/stands/path/masters`。接続方式 A/B/C の自動判定 |
| `bridge.js` | 方式 B 用。ログイン済み km タブに貼る中継スクリプト(読み取り専用) |
| `inject.js` | 方式 A 用。旧画面を新UIに置換するローダー(開発用。mixed content のため https 配信が必要) |
| `serve.ps1` | Windows 用の簡易静的サーバー(Python/Node がない環境用) |

## データの流れ
```
画面イベント → search(q) / tripSearch() / liveLoadMap() / genPath()
   → API.get(path, q)   … mock: MOCK[path](q)   live: live.js が実パラメータへ変換 → fetch or postMessage
   → 正規化した行 → 描画
```
UI 側の行オブジェクトは実 API の列名(`ticketNumber, reservedDate, passengerNameKana, ...`)をそのまま使っている。モックも同じ列名で生成しているので、live に切り替えても描画コードは変わらない。

## 画面と状態
- ルート: `#ticket #map #trip #path #msg-all #msg-one #msg-reply #msg-result #master #csv #sos #slots #funcs`
- 画面切替で `document` に `screen` イベント(`detail.route`)。各モジュールはこれで初期化・再描画
- テーマ: `data-theme` 属性(なし=OS 設定 / light / dark)。`localStorage('km-theme')`
- 期間ピッカー: `R={from,to,kind}` が検索の期間。プリセット 9 種 + 2 か月カレンダー + 時刻
