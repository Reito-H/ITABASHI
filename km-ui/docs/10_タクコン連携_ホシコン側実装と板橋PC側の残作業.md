# 10. タクコン連携 — ホシコン側は実装・本番稼働開始（2026-10-13）。板橋PC側の残作業

## ホシコン側でやったこと
- Tunnel `km-relay` に Public Hostname `takcon.bentenclub.com → http://127.0.0.1:8766` を追加（originRequest.httpHostHeader = `localhost:8766`。
  takcon-sync の HttpListener が Host 名を厳密に見るため、これが無いと「400 Invalid Hostname」になる）。
- Cloudflare Access アプリ `takcon-sync (hoshikon)` をそのホスト名に付与（ホシコンのサービストークンのみ許可。外部からは 403）。
- Worker 側: `system/src/utils/takcon_sync.ts`（pull・取込・R2保存・ack）、`routes/admin_takcon_sync.ts`（設定 → システム →「タクコン連携」画面、今すぐ取込）、
  cron（毎時）に組み込み。`migration_199`（takcon_sync_files / takcon_sync_runs）。
- 取込の対応: 事故データCSV → 事故分析へ反映。ホシコン収集データ → 売上・安全運転データへ反映（大きいので数回に分けて取込）。
  日報データCSV / 駐車料金 / オット → R2（benten-documents の takcon/）に保存のみ（取込処理は未定義。必要になれば追加）。
- 2026-10-13 時点の未処理4件（日報・駐車料金・事故11件・収集データ2934行）をローカルで取込テスト済み。本番は毎時 cron ＋ 画面の「今すぐ取込」。

## 板橋PC側（Windows の Claude）への依頼
1. **serveToken の設定**: `takcon-sync\config.json` の `serveToken` に、Mac 側 `km-ui/relay-pc/takcon_serve_token.txt` の値（git 管理外。ユーザーが手渡し）を設定し、takcon-sync を再起動。
   ホシコン側は既に `Authorization: Bearer <同じ値>` を送っている（secret `TAKCON_SERVE_TOKEN`）。設定後、ホシコンの「タクコン連携」画面で「板橋PC 接続OK」が出ることを確認。
2. ホスト名チェックの件: takcon-sync 側の変更は不要（Cloudflare 側で Host を `localhost:8766` に書き換えて送っている）。
   もし listener の prefix を `http://127.0.0.1:8766/` 固定にしている場合はそのままで動く。`+` / `*` に変える必要はない。
3. 以後の確認は、ホシコン → 設定 → システム → 「タクコン連携」で「最終取込」「失敗」を見る。失敗が続く場合は内容欄のメッセージを Mac 側に共有。

## 注意
- Cloudflare の Browser Integrity Check により、Python の urllib 等（素のUA）で takcon.bentenclub.com を叩くと 403（error 1010）になる。curl や Worker からは通る。
- ホシコン側は成功したファイルだけ `/ack` する。失敗したファイルは ack しないので、PC 側の未処理一覧に残り、次回再試行される。
